## 每週詳細學習內容

下面不是要背完的章節清單，而是每週 5 小時的「學習腳本」。每一週都先做預測，再動手執行；遇到錯誤先分類為語法、資料、數學、概念或判斷問題。每週的完成條件比看完多少頁更重要。

### 第 1 週：確認起點，建立可解釋的 Python 小流程

**本週要學會：** 用 list、dict、函式與基本資料處理完成一個小任務；分辨資料缺值、評估指標與模型可靠性不是同一件事；把技術概念說成別人能回答的問題。

**技術實作 A（75 分鐘）：** 先讀 Python Tutorial 中的控制流程、資料結構與函式，接著建立 8 筆月份／訪客數資料。刻意打亂月份並放入一個空值，寫出排序、缺值標記、平均數函式與 MAE 函式。每個函式都寫一句「輸入是什麼、輸出是什麼、空值怎麼處理」。

**技術實作 B（75 分鐘）：** 用 `[110, 130, 120]` 和 `[100, 140, 125]` 手算並執行 MAE；再預測 `shift(1)`、`shift(-1)` 和 `shift(1).rolling(3).mean()` 的結果。最後重寫一個第一次卡住的函式，不直接複製答案。

**思考／教學／溝通：** 把「我想加強 ML」改成三個可觀察的能力問題。準備一個 3 分鐘解釋，先問聽眾是否知道平均數、時間順序和預測，再用一題新資料檢查理解。對話時先重述對方的決定與顧慮，再問一個澄清問題。

**完成條件：** 一個可重跑的 `.py` 或 notebook、MAE 計算、卡點分類表，以及一段能說明「三筆資料不足以證明可靠」的錄音。

**自我檢查：** 如果把空值由 120 改成 0，你的平均數會如何變？這是資料清理問題、評估問題，還是兩者都有？

### 第 2 週：把原始資料對齊成特徵與目標

**本週要學會：** 理解 `shift`、rolling mean、目標欄位和預測時間的關係；知道「可以計算」不等於「在當時可以取得」；使用小表格查出日期錯位。

**技術實作 A（75 分鐘）：** 閱讀旅遊預測專案的 `load_data` 和 `feature_frame`。不用整個專案，自己造 6–12 列日期資料，逐列寫出前一期值、前三期平均和下一期目標。先畫出「資料產生時間 → 預測時間 → 目標發生時間」。

**技術實作 B（75 分鐘）：** 把資料日期改成不連續、加入第一期沒有 lag 的情況，檢查程式是否仍正確。再故意把當期訪客數放進特徵，寫下為什麼這可能是洩漏，而不是只看模型分數。

**思考／教學／溝通：** 將「特徵能預測未來」拆成主張、理由、假設和反例。畫一張給初學者看的資料流圖，並設計一道把預測日往後移一天的新題。把「你想要什麼功能」改問成「你要做哪個決定、現在卡在哪裡」。

**完成條件：** 一個 6–12 列的特徵表、資料字典、日期對照圖，以及一段指出可能洩漏欄位的說明。

**自我檢查：** 你是在月初、月底，還是下一個月開始時做預測？如果回答不清楚，模型的 MAE 也不能被正確解讀。

### 第 3 週：先建立基準，再談模型好不好

**本週要學會：** 使用 last-value 或平均值基準；用同一份時間切分比較簡單迴歸；分辨 MAE、R²、預測與因果解釋的不同用途。

**技術實作 A（75 分鐘）：** 先用上一期值預測下一期，記錄每筆誤差。再用同一切分訓練簡單線性迴歸，只加入前一期和 rolling mean。表格固定記錄資料範圍、特徵、MAE、R² 和執行日期。

**技術實作 B（75 分鐘）：** 改一個特徵或切分點，預測分數會先寫下來再執行。檢查係數只能說明模型在資料中的關聯，不把較低 MAE 寫成「找到原因」。

**思考／教學／溝通：** 用一個生活例子解釋「相關不等於因果」，再讓聽眾回答新的例子。用 90 秒向非技術聽眾說明模型結果，結尾一定問「你會因此採取什麼行動？」以確認模型是否真的對決策有用。

**完成條件：** 基準／迴歸比較表、一次改題結果，以及一個可能誤導人的結論和修訂後句子。

**自我檢查：** 如果模型比基準好 2%，但每月成本會增加，你還會採用嗎？還需要什麼資料才能判斷？

### 第 4 週：找出資料洩漏，學會時間序列驗證

**本週要學會：** 指出特徵在預測當下是否可取得；理解 train／validation／test 的角色；知道 Pipeline 能防止哪些前處理錯誤、不能替你解決哪些時間問題。

**技術實作 A（75 分鐘）：** 閱讀 scikit-learn 常見錯誤與 cross-validation 文件，標出預測時間、標籤可取得時間、切分點。用小資料故意先對全部資料做縮放，再切分；保存錯誤分數與正確分數。

**技術實作 B（75 分鐘）：** 用時間順序切分或 rolling backtest 重做一次，將縮放器放入 Pipeline。逐項寫出「哪一行造成洩漏」「為什麼分數會變」「修正後能支持什麼結論」。

**思考／教學／溝通：** 回顧自己是否偏愛好看的分數。替一份錯誤答案寫三句回饋：指出行為、說明影響、給出下一步。角色演練「分數很好，直接用吧」，先確認目標和時間範圍，再回應限制。

**完成條件：** 一份驗證說明、一個錯誤／修正版比較表，以及第 4 週檢查記錄。若仍不能說清楚洩漏，下一週先補強，不急著進 DL。

**自我檢查：** 只要用了 Pipeline，就一定沒有洩漏嗎？請舉一個「欄位本身在預測時尚未存在」的例子。

### 第 5 週：用正則化做有理由的參數實驗

**本週要學會：** 理解過度擬合、正則化與 Ridge 的基本作用；知道參數選擇必須先指定規則；分清驗證資料與最終測試資料。

**技術實作 A（75 分鐘）：** 讀 Statistical Learning 的 regularization 段落，先預測 alpha 變大會讓係數如何改變。只試三個事先指定的 alpha，使用相同切分，記錄訓練／驗證 MAE 和係數大小。

**技術實作 B（75 分鐘）：** 將標準化與 Ridge 放入 Pipeline，畫出三個參數的誤差比較。不要因為結果不漂亮就增加十個參數；寫下「我選哪個、依據是什麼、測試集何時才使用」。

**思考／教學／溝通：** 從個人預設與群體壓力各找一個行為解釋，並列出另一個可能解釋。用具體圖例教正則化，再讓聽眾判斷新例子。面對不同意見時，先說出對方最合理的顧慮，再說你的判斷。

**完成條件：** 一次有預先假設的參數實驗、誤差圖、選擇理由和一段 2 分鐘解釋。

**自我檢查：** 如果驗證分數變好，但係數變得難以解釋，你要用什麼額外條件決定是否採用？

### 第 6 週：比較模型，也比較錯誤發生在哪裡

**本週要學會：** 理解樹模型和 ensemble 的基本取捨；不把 feature importance 當成因果；用不同時期或情境的錯誤檢查模型是否穩定。

**技術實作 A（75 分鐘）：** 讀 Tree-Based Methods，加入一個小型 Random Forest。固定資料、切分和指標，與 Ridge、基準放在同一表格；不先調參，先理解模型差異。

**技術實作 B（75 分鐘）：** 將誤差按月份或資料情境分組，找出平均分數掩蓋的失敗案例。檢查 feature importance 只能回答「模型使用了什麼」，不能直接回答「什麼造成結果」。

**思考／教學／溝通：** 分析「平均分數比較好」漏掉哪些情況。用兩個相似但答案不同的案例檢查遷移理解。練習說明為什麼選簡單模型，或明確承認資料不足，不只引用模型名稱。

**完成條件：** 一頁模型選擇備忘錄，包含基準、Ridge、Random Forest、失敗情境、決策與停止條件。

**自我檢查：** 若 Random Forest 平均 MAE 最低，但在你最在意的月份最差，你會怎麼報告？

### 第 7 週：重新檢查舊報告中的主張與證據

**本週要學會：** 把報告中的結論拆成可核對的主張；分辨描述、預測、因果建議和未知；在不能重算時誠實標示證據界線。

**技術實作 A（75 分鐘）：** 打開自己的 YouTube 舊報告，挑三句最重要的結論。對每句填「使用資料、指標、比較對象、時間範圍、是否可重現」。先不改結論，先找它需要的證據。

**技術實作 B（75 分鐘）：** 用 Python 做一張描述圖或重新計算一個可確認的統計量。若找不到原始資料，就把狀態寫成「未驗證」，不以記憶補足。將 R² 等指標翻譯成不過度承諾的語句。

**思考／教學／溝通：** 把「多發影片會讓觀看變差」改寫成至少兩個競爭解釋。設計一個把特徵重要度當原因的錯誤答案，再用問題引導學習者自己發現缺口。向合作夥伴說明目前知道、不知道、下一步需要什麼證據。

**完成條件：** 一張描述圖、三項主張的證據核對表，以及一段 150 字的限制說明。

**自我檢查：** 哪一項新證據會讓你撤回或改寫其中一個結論？請具體寫出資料欄位或觀察結果。

### 第 8 週：設計小實驗，理解行為而不是猜測行為

**本週要學會：** 寫出假設、單位、介入、指標、比較組、限制、護欄指標和停止條件；知道合成資料能練設計，不能證明真實世界效果。

**技術實作 A（75 分鐘）：** 以小型合成資料模擬兩組比較。先寫研究問題和預期方向，再決定分組方式與主要指標；最後才產生資料。將每一步和真實資料中的待確認事項分開。

**技術實作 B（75 分鐘）：** 改變樣本數、效果大小或雜訊，觀察結論是否穩定。用簡單圖表呈現估計差異與不確定性，不把一次模擬當成產品成功證據。

**思考／教學／溝通：** 將一個人的行為拆成觀察事實與可能解釋。設計前測和不同表面的後測題，說清楚每題能檢查什麼、不能證明什麼。練習在時間有限時列出共同目標、限制、兩個方案和下次確認點。

**完成條件：** 一頁小實驗設計、模擬圖、至少兩個替代解釋，以及第 8 週檢查記錄。

**自我檢查：** 如果兩組結果不同，你如何知道是介入造成，而不是原本兩組就不同？

### 第 9 週：從線性模型進入神經網路與張量

**本週要學會：** 看懂 tensor、shape、layer、activation、forward 和 loss；理解神經網路先是可計算的函式，不是神秘的黑盒子；知道小資料不一定需要 DL。

**技術實作 A（75 分鐘）：** 讀神經網路的單層／多層概念，手算一個 2 維輸入、2 個權重和偏差的線性層。把每個數字標成 shape，核對輸出是否符合矩陣運算。

**技術實作 B（75 分鐘）：** 用 PyTorch tensor 重做同一個 forward，改變 batch size 和特徵數，讓程式報錯後讀懂錯誤訊息。寫一張「輸入 → layer → activation → loss」流程圖。

**思考／教學／溝通：** 列出使用 DL 的理由和目前沒有必要的理由。把 neural network 拆成輸入、參數、輸出、錯誤四個小概念，最後用一句話向熟人說明何時值得多花時間試新技術。

**完成條件：** 張量 shape 筆記、一次手算／程式核對、流程圖，以及一份「不用 DL 也合理」的條件說明。

**自我檢查：** 若輸入 shape 是 `(32, 10)`，32 和 10 各代表什麼？哪一個改變不應改變模型的特徵數？

### 第 10 週：建立 PyTorch 模型，理解資料批次與梯度

**本週要學會：** 使用 Dataset、DataLoader、`nn.Module`、forward 和 autograd；知道一個 batch 的資料形狀與標籤形狀；能用小數字核對一次梯度，而不是只相信訓練完成訊息。

**技術實作 A（75 分鐘）：** 跟著 PyTorch Learn the Basics 建立 FashionMNIST 的小樣本 DataLoader。印出一個 batch 的 shape、標籤和數值範圍，先預測再執行。

**技術實作 B（75 分鐘）：** 建立最小分類網路，執行一次 forward 和 loss；用一個 scalar 線性例子手算梯度，再和 autograd 結果比較。將每個 tensor 的 shape 寫在註解中。

**思考／教學／溝通：** 檢查「程式可以跑」到底支持哪些結論。先用一個 tensor shape 例子教學，再換 batch size 出新題。讓對方打斷你的解釋，記錄他在哪個詞失去理解並重寫說法。

**完成條件：** 一份有註解的 notebook、資料批次檢查、一次 forward／loss、一次梯度核對和中斷點記錄。

**自我檢查：** 模型輸出 logits 的 shape 應該如何對應 batch size 和類別數？如果對不上，先查哪三件事？

### 第 11 週：訓練、驗證、除錯與儲存模型

**本週要學會：** 分辨 loss、optimizer、learning rate、epoch、validation 和 test；從訓練／驗證曲線找出至少兩種可能解釋；能儲存並重新載入模型。

**技術實作 A（75 分鐘）：** 寫出清楚的 training loop 和 validation loop，將官方訓練資料再分驗證集，測試集留到最後。只比較兩個 learning rate，先寫預期再執行，保存 loss 和 accuracy 曲線。

**技術實作 B（75 分鐘）：** 練習 `state_dict` 的儲存／載入，重新載入後比較同一批輸出。製造一個可控錯誤，例如忘記切換 `eval()` 或標籤型別不對，記錄症狀、原因、修復和預防方式。

**思考／教學／溝通：** 對「訓練 loss 降低、驗證結果沒有改善」列出至少兩種解釋，為每個解釋提出區分方法。用一次具體回饋指出行為與影響，詢問對方考量，再共同決定下一步。

**完成條件：** 兩次學習率實驗、訓練／驗證圖、模型存取核對，以及一份除錯紀錄。

**自我檢查：** 驗證集變好就代表測試集一定變好嗎？如果不能，還有哪些選擇偏差？

### 第 12 週：完成一個可重跑實作，並教懂別人

**本週要學會：** 把資料、切分、基準、模型、指標、限制和下一步串成一個判斷；能修改程式而不是只重跑；能透過新題和回饋檢查教學是否有效。

**技術實作 A（75 分鐘）：** 從乾淨執行狀態重跑一個旅遊 ML、YouTube 診斷或 FashionMNIST 小實作。先固定資料版本和執行順序，產生基準、主要模型、指標與錯誤摘要。

**技術實作 B（75 分鐘）：** 改一個條件，例如預測窗口、特徵、切分或 learning rate，記錄結果是否改變。最後寫「什麼證據會讓我換模型」「哪些問題模型仍不能回答」「何時停止投入」。

**思考／教學／溝通：** 做 8 分鐘微型教學，必須包含先備問題、具體例子、練習、新題和理解檢查。再做 3 分鐘建議說明，回應 2 個異議，記錄你修正了哪個假設。沒有真人時只能標記「待真人驗證」，不把 AI 的稱讚當成理解證據。

**完成條件：** 一個可重跑實作、一頁決策說明、教學錄音或現場紀錄、聽眾新題回答，以及第 12 週自評四級紀錄。

**自我檢查：** 如果最後模型分數沒有變好，但你能指出洩漏、限制和下一個最有價值的資料，你是否仍完成了本週的學習目標？請用證據回答。

## 第一週的短實作：先確認，不預設能力

這是 75 分鐘的第一個技術時段。可以查官方語法，不使用 AI 生成完整解答。先記錄你獨立能做到哪裡，再接受提示。
