# 实体课 OpenSlide 回归原因与当前防线

日期：2026-10-21  
范围：复盘 W06 第13—14课实体课草稿在布局、重复活动格式、路线页、完整口语范例和末段开放题上的回归。本文是事件与实现状态记录，不新建批准、权威或发布规则。

## 结论

问题不是单一 CSS 失误，而是输入、制作、检查和报告之间没有一条可追溯的逐页约束链。作者一边复制／手工改写不同版本的页面，一边用偏向当前课件的检查器验证；人工视觉复核又只覆盖部分页面。于是页面可能通过有限的结构检查，却仍偏离已核准范例，或有页面未被逐一查看。后续修正过的版面也未必同步进作者说明、规则和检查器，导致错误预期继续传播。

## 已确认的根因

1. **参考分工写错且跨文档漂移。**旧指引把 L9–10 同时说成封面、路线和活动页基准；真实标准是 L9–10 提供封面与整体视觉，L11–12 提供路线图标卡，正文按最近核对过的同类活动页复用。把所有页面都从一套视觉样式推导，会让“像同一套课件”取代“同题活动沿用原格式”。
2. **同类活动靠手动平行复制。**学生页、教师稿、说明、清单、静态检查与渲染报告是分开维护的文件；并没有共同的逐页契约作为单一输入。更新一处后，其他副本可保留旧页号、旧题型或旧内容。W06 README 之前只指向 v02，漏掉 v03 对第13—18页的修订，正是输入路由不完整的实例。
3. **静态 checker 有课次专属假设。**`scripts/check_open_slide_visual_consistency.py` 内含 W06 稳定 ID、题目文案、HSK 模型与页面位置等检查，适合检查这份课件的约定，却不能证明任意新课都遵循正确的重复活动模板。把它当通用检验会造成“脚本通过即版式正确”的错误预期。
4. **渲染核验覆盖面不等于完整证据。**修复前的浏览器脚本输出逐页截图与部分元素测量，并等待 `document.fonts.ready`；同步校验报告的 HTML／checker 哈希、页数与页号、issues 和两项负向检查。但同步没有要求截图文件逐页存在／可读，也没有强制每页每类关键元素都有测量；修复前的报告仍可在部分几何字段缺失时满足同步条件。代码不读取每页的 `id` 或 `expected_text` 对照，也没有针对任意页面的字体角色清单。渲染脚本和报告不能替代全页、全尺寸人工复核。
5. **作者把意图写成了错误预期。**当源文案、README、静态期望和成品 HTML 各自手动更新时，错误规则可以被写进“预期”并自我验证。W06 专属 HSK 和页面措辞曾被活动流程写成普遍默认；正确边界是按当前班级核准范围和熟练度决定，只有本届已批准计划明确采用时才标 HSK。W06 确实保留 HSK 1–3／HSK 4–6，但不能推广到其他班。
6. **重复 CSS 与固定高度增加局部修补风险。**W06 HTML 存在重复选择器与后置覆盖（例如 `.report-phrase`、`.discussion .icon-prompt`），并使用固定高的布局容器。作者只改前面的基础声明或增加局部覆盖时，最终生效值可能与看到的首条规则不同；固定高度再叠加长范例／边界变化，会造成内容挤压或贴近页脚。必须核对完整 cascade 与浏览器实际几何，不能只看 CSS 片段。
7. **报告把不同完成状态压成一句“通过”。**同步成功、checker 通过、截图存在、逐页已人工查看、教师实播和课堂验收是不同证据。旧报告若不列明页面覆盖、检查器、输入哈希和未验证项，读者很容易把有限自动检查理解成“全套视觉 QA 完成”。

## 本次已实现并验证的修复

- **参考入口统一：**生产技能、活动流程、HTML标准、工作区adapter均采用L9–10封面／整体视觉、L11–12路线、同类活动参考分工；修正README的v02第1—12页／v03第13—18页范围。具体HSK标签按班级核准范围，W06仍用两档。
- **逐页完整内容核对：**新增 `classroom_slide_contract.py` 和本课 `lesson-13-14-slide-contract.json`，绑定已审阅输入哈希、稳定ID、完整文字、角色、页序、每页允许的图片（包括无图片页）、路线卡数／列数和题目／支持页配对。公共检查入口读取本课契约；历史W06断言明确隔离到测试辅助路径。契约是技术映射，不是新批准记录，不允许从待验HTML反向生成自证预期。
- **通用浏览器检查：**逐字读取所有可见文字，检查实际字号／字体、变换后字号、图像、绘制元素、画布边界、页脚留白与页面结构；封面和路线也有有限测量。路线沿用无页脚参考，明确记录合成底部保留线，不能把缺测量写成通过。
- **证据实时复核：**schema v2绑定HTML、原始契约、素材、检查器、每页测量和保存的截图哈希；同步核对课次、owner、source、draft manifest及现有批准，再重渲染只读复验。不能用只有页号和PASS的JSON通过同步。跨次Chrome图像栅格化可能不同，因此像素字节差异仅记诊断；文字、字体、几何、素材和已保存截图的完整性仍为硬性检查。
- **现有课件修复：**补回第9页原稿的“两人讨论，推荐一件衣服，并说明理由。”，补回第3页“他为什么”的“他”，将第11页末尾标点与核准文案一致。调整图片区留出空间，未改批准输入；移除5条完全被后续覆盖的重复CSS规则。
- **统一执行入口：**`python3 scripts/verify_classroom_slides.py --deck-id <登记ID> --sync --build`串联现有preflight、契约、浏览器、同步和构建，不增加审批轮次。

验证记录：43项Python测试通过；9项浏览器故障用例均被正确拒绝；另有非W06模板、不同路线卡数／列数、伪造／缺失报告和错课次测试。当前18页全文契约与浏览器检查通过，实际统一首页18页及前后翻页检查通过；最小页脚间距71.594px（要求64px）。已查看全课contact sheet及本次变更页全尺寸截图。详细证据位于 `.agent/runs/classroom-slide-controls-20261021/`。

自动检查仍不能证明教学任务被学生理解或替代美感判断；这些继续由制作者按同一清单完成读者理解和整套视觉复核。不得把技术通过写成教师试教、课堂验收或正式发布通过。

## 唯一操作清单与报告边界

制作时只按[实体课标准「后续制作的默认执行与交付自检」及2026-10-20补充](../classroom-html-standard-2026-10-07.md)执行视觉复用、内容核对、逐页渲染、统一首页检查和记录；活动内容仍按[实体课活动制作流程](../classroom-activity-workflow.md)设计。本文不增加另一份 checklist，也不添加审批轮次。

完成报告应逐项说明：检查的课次／源文件版本与哈希；封面、路线、同类活动分别采用的参考；静态 checker 与浏览器报告覆盖的页数和输入哈希；逐页人工查看的截图／接触表位置；未运行或未覆盖的检查；教师实播、rehearsal、课堂验收及发布各自的实际状态。没有逐页证据时，只能报告部分检查完成，不能写“全部页面已检查”。
