# 荣市大学_学生管理系统：学习成效追踪 V1 产品规格

## 1. 产品边界

V1 是教师单人使用的课堂记录系统。随机点名继续负责「抽到谁、是否回答、何时完成」；学习成效追踪负责身份、班级、课程、出席、活动、评分、课后汇总与长期学生历程。机器学习不参与评分，只在资料累积且品质达标后，使用去识别化资料做低风险辅助分析。

### 三层范围

- **现有随机点名：**每堂课建立新 session；本轮已回答者不再被抽，未回答者仍在 drawing pool；保存抽取、未回答、评分、撤销以及当时的教材、课次和 rubric 快照。
- **V1 新增：**教师登入；学期、班级、学生、修课、教材、课次、活动、出席、学习表现、课后汇总、学生历程与 follow-up。
- **未来 ML：**只使用去识别化、结构化、教师确认的资料提供趋势或复核提示；不自动决定成绩、能力等级、纪律处置或排名。V1 不收音、不录像、不转写。

## 2. Teacher flow

1. 教师登入，进入「今天的课堂」。
2. 选择班级、日期、教材、课次与活动；系统带入名单和 rubric 版本。
3. 开始 session，以例外方式记录缺席、迟到、请假，再确认其余到课。
4. 随机点名产生课堂事件。回答后，教师按 rubric 评分并可「储存并抽下一位」；未回答者留在本轮。
5. 没有待评分学生时可切换教材、课次或活动；既有记录保留原快照。
6. 关闭 session 前检查未评分资料；关闭后显示覆盖率、已回答／未回答、各指标分布、出席例外和待跟进学生。
7. 教师确认汇总、建立 follow-up，并从学生历程查看长期变化或修订错误。

## 3. Fields / non-fields

### 必须字段

| 对象 | 字段 |
|---|---|
| 权限 | `owner_id`、教师帐号、建立／更新时间 |
| 学期与班级 | 学期、班级代码／名称、状态 |
| 学生 | 系统 ID、学号、姓名、启用状态；同名以学号区分 |
| 修课 | 班级、学生、加入／退出日期、状态 |
| 教材／课次 | `textbook_key`、教材名、`lesson_key`、课序、课名；课次只在教材内唯一 |
| Session | 班级、日期、开始／结束时间、状态、课后反思 |
| 活动 | session、教材、课次、类型、任务模式、表现目标、rubric 版本 |
| 出席 | session、学生、状态、可选短备注、记录时间 |
| 回答尝试 | session、活动、学生、轮次、结果、抽取／完成时间、是否计分、事件来源、幂等键 |
| 评分 | rubric 版本、criterion 分数、总分、评分状态、可选备注、修订时间 |
| Follow-up | 学生、来源 session、原因分类、到期日、状态、完成时间 |

### 不收集或默认不导出

- 音频、视频、照片、逐字稿和每一道题目的完整文字。
- 健康、家庭、民族、宗教、政治观点等敏感资料。
- 密码明文、service role key、浏览器调试资料。
- 人格标签或模型推断的 ACTFL 等级。
- 教师自由备注默认不进入 ML 导出。

语义必须分开：`not_answered` 不等于零分；缺席不等于未回答；未评分不等于低分。

## 4. Supabase tables and relations

现有 `academic_terms`、`courses`、`students`、`enrollments`、`class_sessions`、`attendance_records`、`observation_records`、`followups` 保留。`courses` 在 V1 视为一次实际开课／班级，不另建重复的 `classes` 表。

| 新表 | 关键关系与用途 |
|---|---|
| `textbooks` | `owner_id`；教材稳定识别码与名称 |
| `lessons` | 属于 textbook；`unique(owner_id, textbook_id, lesson_key)` |
| `rubrics` | 名称、版本、状态；启用后不可原地改写历史版本 |
| `rubric_criteria` | 属于 rubric；指标、顺序、分数范围 |
| `rubric_levels` | 属于 criterion；分值与教师可见描述 |
| `activities` | 属于 session，可连 lesson 与 rubric；记录任务类型与目标 |
| `randomizer_rounds` | 属于 session；轮次、开始／完成时间、状态 |
| `response_attempts` | 属于 round、activity、student；结果、时间、计分状态、来源事件、幂等键 |
| `criterion_scores` | 属于 response attempt 与 criterion；结构化分数 |

关系原则：

- `class_sessions` 可有默认教材／课次，但切课后不回写旧记录。
- `observation_records` 保留为每堂课每位学生的综合观察；其现有唯一约束不适合承载多次回答。
- 课后汇总先由 SQL view／查询产生，避免重复统计漂移；需要教师锁定时再加入版本化 snapshot。
- 每张表都有 `owner_id`，跨表以 `(owner_id, id)` 复合外键避免跨帐号误连。
- 随机点名每个事件提供稳定 `source_event_id`／`idempotency_key`；断网重送使用 upsert，不重复记分。
- Supabase 是正式资料来源；本机资料只能标为待同步、可重试，不能与云端同时声称是 authority。

## 5. ML labels, features and quality

### 可考虑的教师确认标签

- 下一次同指标是否进步。
- 教师是否建立／完成「需要再次观察」。
- 活动是否独立完成、提示后完成或未回答。
- rubric 各 criterion 的教师评分。

这些是辅助研究标签，不是自动成绩真值。

### 可用特征

- 随机化学生代号、教材／课次／活动类型、rubric 版本。
- 距上次回答天数、历史尝试数、未回答比例、近期出席率。
- 历次 criterion 轨迹、提示需求、活动完成状态。

### 禁用特征与品质门槛

- 禁用姓名、学号、电邮、原始备注、音视频、敏感人口资料，以及可直接重新识别个人的小班级组合。
- rubric 版本不可漂移；同一分数必须有相同定义。
- 明确区分零分、未评分、未回答、缺席与资料缺失。
- 幂等键无重复，时间戳完整，教材＋课次组合合法。
- 建模前报告每班、每课、每 criterion 的样本量、缺失率、标签分布与时间漂移。
- 先做简单基线和人工审核；小样本或跨班不稳定时停止建模，不输出学生级预测。

导出由受控后端任务或 Edge Function 产生去识别化 CSV／Parquet；不允许客户端下载含身份的全库再手工去识别。

## 6. Privacy, RLS, backup and keys

- Supabase Auth 关闭公开注册，仅管理者建立教师帐号。V1 虽为单教师，schema 仍保留 owner 隔离。
- 每张表启用 RLS；authenticated 只能 CRUD 自己的 `owner_id`，anon 无权限。
- 自动测试两位 owner：A 不能读取、写入、更新、删除或通过外键关联 B 的任何记录。
- 前端只使用 publishable key。service role key 只放受控后端／CI secret，绝不进入 Git、浏览器 bundle、localStorage 或课堂电脑备份；日常教师 CRUD 不使用 service role。
- 启用 Supabase 平台备份，并定期产生应用层加密导出；至少每学期演练一次还原，核对记录数、外键和抽样内容。
- 建立保留、导出、更正与删除流程。删除学生前先确认成绩保存义务，必要时停用或去识别化，不直接级联删除历史成绩。

## 7. Phases and acceptance

### Phase 0：资料契约

对齐随机点名事件、既有 tracker 与新表。验收：字段映射覆盖抽取、未回答、评分、切课、撤销和关课；无同义重复实体。

### Phase 1：正式 Supabase

建立正式项目、迁移新表、汇入三班、加唯一约束和 RLS 测试。验收：教师能登入；名单与来源一致；跨 owner 全拒绝；anon 无读取；service key 不在客户端。

### Phase 2：随机点名整合

写入 `response_attempts`，支持离线排队、幂等重送。验收：整堂课无漏写／重复；未回答不产生零分且留在池中；切课不改旧记录；重送不增加记录数。

### Phase 3：课堂与课后闭环

完成开课、出席、活动、rubric、关课、汇总、学生历程和 follow-up。验收：核心动作不拖慢课堂；关课前能发现待评分；汇总可追溯；更正保留时间与操作者。

### Phase 4：去识别化导出

建立受控导出、资料字典和品质报告，不训练高风险模型。验收：无直接识别字段／自由备注；同一导出内假名稳定；缺失语义、版本和样本量可验证。

### Phase 5：课堂试用

先用一班、两至三堂课，再扩到三班。验收：教师确认顺手；云端／离线恢复无资料损失；完成一次备份还原；阻塞问题关闭才上线。

## 8. Risks and stop conditions

- 姓名当主键会合并同名学生：使用稳定 student ID／学号。
- 裸 `lesson-01` 会跨教材冲突：使用教材＋课次。
- 双资料源会让成绩分歧：正式库与待同步状态必须清楚。
- rubric 改版会破坏趋势：历史固定版本，不原地改写。
- 自由备注可能泄露隐私：默认不进入分析导出。
- 小样本预测会误导：未达门槛只做描述统计。
- 任何 RLS 越权、重复写入、离线资料遗失或备份无法还原，都是停止上线条件。
