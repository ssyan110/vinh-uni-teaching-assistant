# 学校出勤系统对接：只读安全评估与方案

评估日期：2026-09-05

## 当前结论

- 本次只检查 `student-tracker` 本地代码、迁移和项目文档，没有访问学校出勤系统、学校网站或任何外部接口。
- 没有读取、使用、保存或写入任何账号密码、验证码、cookie、私钥或 service role key。
- 没有复制学生姓名、学号、邮箱或其他学生个人资料。当前应用的出勤记录只属于本系统自己的数据边界，不代表已经和学校系统打通。
- 当前代码没有学校系统 endpoint、浏览器直连、自动登录或外部同步任务；因此“学校出勤整合”目前是未连接状态。

## 已检查的本地安全边界

1. 教师登录只使用本应用自己的 Auth 配置；前端配置缺失时保持登录表单，但明确提示无法登录的原因。
2. 本应用自己的数据库表使用教师 owner 隔离和 RLS 设计；正式对接前仍需在学校批准的测试环境中复核远端策略。
3. 出勤状态在本系统内由教师主动记录；不得把本地出勤表当成学校系统的权威结果，也不得静默覆盖教师记录。

## 建议的安全对接架构

学校系统若要提供数据，必须由学校 IT／教务单位先提供正式、获批准的只读 API 或受控文件导出。浏览器不直接访问学校系统，前端也不保存学校账号密码。

1. 由学校指定资料负责人、系统负责人和测试环境；确认用途、法律依据、保留期限与更正流程。
2. 优先使用学校批准的 OAuth／SSO 或后端服务身份，并只授予出勤读取权限。禁止通过模拟网页登录、共享教师密码、验证码转发或抓取 cookie 对接。
3. 连接凭据只放在受控后端的 secret manager；不进入前端环境变量、Git、localStorage、日志、截图或交付包。当前 student-tracker 不新增此连接，也不部署后端代理。
4. 默认只允许传递“课程、日期、课次、出勤状态、不可直接识别的外部记录标识”等最小字段。姓名、学号、邮箱、生日、联系方式、备注和整份名册不得复制进本系统。
5. 如果学校系统只能提供带姓名／学号的资料，先停止整合；由学校批准匿名化或一次性人工核对方案，并在内存中完成映射后立即丢弃原始资料，禁止落盘。
6. 同步采用只读、幂等、可审计的拉取；失败不覆盖本系统原纪录，重复拉取不重复建立事件。每次同步记录操作者、范围、时间、结果和错误类别，但不记录 token 或学生个人资料。
7. 上线前用合成学生 ID 做沙盒测试：验证最小权限、跨教师隔离、日期／课程映射、重复拉取、撤销权限、超时和异常恢复；未通过任一项就不进入真实资料测试。

## 具体阻塞与下一步

目前缺少以下学校侧输入，因此不能安全实现真实整合：

- 官方 API 或受控导出规格、测试环境和联系窗口。
- 学校批准的身份方式与明确的只读权限范围。
- 课程／课次／出勤状态的字段字典，以及不含真实学生资料的合成测试样本。
- 资料负责人对最小化、保留、删除、纠错与审计的书面确认。
- 不依赖姓名／学号的稳定对账键；如果不存在，需先由学校批准替代方案。

下一步应由学校 IT／教务单位先提供上述资料；收到并完成安全审查后，才可在独立后端设计只读 adapter 和审计测试。本轮不访问外部系统、不创建连接、不导入学生资料，也不部署。

## 停止条件

出现以下任一情况立即停止：要求提供或复用教师密码、必须在浏览器保存学校 token、需要复制完整名册、只能使用非官方抓取、无法确认资料授权／删除流程、跨教师读取可行，或同步会覆盖本系统既有出勤记录。
