# 荣市大学听力练习 · 共享服务器版

这是可以自行托管的 Node + Vite 应用。学生与教师通过同一个 HTTPS 地址访问，共享提交记录。当前没有配置云平台、Supabase 或公开域名，也没有部署。

## 启动

使用 Node 20 或以上版本，进入本目录：

```sh
npm ci
npm run build
export TEACHER_PASSWORD='<自行设置的至少12位密码>'
export PUBLIC_ORIGIN='http://localhost:4173'
npm start
```

密码只从环境变量读取，不提供默认密码。不要把实际密码写入 Git。默认只监听 `127.0.0.1:4173`。开发本机可以使用 HTTP；其他网络需要下方的 HTTPS 托管设置。`npm run dev` 仅运行 Vite 页面，不提供正式 API；正式验证请使用 `npm run build` 后的 Node 服务。

可配置：`PORT`、`HOST`、`PUBLIC_ORIGIN`、`TEACHER_PASSWORD`、`DATA_DIR`、`NODE_ENV`。`PUBLIC_ORIGIN` 必须是完整且无路径、无尾斜杠的来源，如 `https://listening.example.edu`。浏览器的 POST 来源必须与它一致。

## 教师操作

1. 打开“教师入口”，用环境变量中的密码登录。
2. 下载流程测试模板，理解字段后导入自己的 JSON。模板是合成测试内容，不是批准教材。客观题仅支持选择题；正确答案只存服务器。开放题指定 `grading: "manual"`，不得填写标准答案。
3. 每个题组填写 `id`、新的 `version`、完整 `lessonKey`（如 `boya-quasi-intermediate-i:lesson-01`）、`sourceStatus`、`status`、音频标示和题目。正式题组的 `status` 为 `approved`，另填写真实 `approvalReference`。该声明由教师负责，不会给仓库教材创造批准记录；未批准教材不得按正式题组发布。
4. 发布时选择固定版本、班级标识、练习名称和截止时间。每行名单为 `学生编号,个人进入码`，编号必须唯一，进入码至少 8 位；建议使用独立随机的 16 位以上进入码，私下逐人分发。学生不能只凭编号冒用别人。练习码与个人进入码缺一不可，分享个人进入码仍会导致身份冒用。
5. 复制生成的学生链接给该班。学生填写编号、个人进入码，先看题目、听音频、答题并提交。音频可以是经核实的 HTTPS 文件，或留空由教师外部播放；工具不核实教材音轨，也不改变 PPT 音频规则。
6. 刷新后查看未提交编号、每次作答和客观题逐题错误数。错误统计按该练习全部尝试计算，重做计入分母。开放题未批阅时分数为空，教师填写实际分数和反馈。每次批阅都有追加历史，原答案不被改写。
7. 学生通过“我的反馈”查看本人提交和教师反馈，不会取得别人作答、名单、个人进入码或正确答案字段。教师可导出本练习 CSV，单元格有公式注入防护。

同一题组 `id + version` 不可覆盖。修改内容时导入新版本，再发布新的练习。已发布练习永远绑定当时的题组版本及名单。关闭或过期后阻止进入和新增提交；已成功提交但未收到网络响应的相同重试仍能取得原回执。重新练习明确新增一次尝试。如果回执丢失后修改答案，服务器返回冲突时页面显示已存提交；学生可查看自己的评分，或明确选择“开始新一次练习（清空草稿）”重新答题。未做该选择前不会覆盖或新增记录。学生本页的答案与重试编号暂存于浏览器会话，只有服务器确认成功后才清除。

## 跨网络 HTTPS 托管

在已授权的服务器上部署 Node 服务并建立域名、证书及持久化磁盘；在相同域名反向代理 `/` 到 `127.0.0.1:4173`。例如 Caddy（示例域名须替换）：

```caddy
listening.example.edu {
  reverse_proxy 127.0.0.1:4173
}
```

服务环境须设 `NODE_ENV=production`、`PUBLIC_ORIGIN=https://listening.example.edu`、安全的 `TEACHER_PASSWORD`，以及固定 `DATA_DIR`。生产环境拒绝 HTTP PUBLIC_ORIGIN，登录 Cookie 使用 HttpOnly、SameSite=Strict、Secure。保持代理和应用同源；勿把本机 Vite 或历史静态站点当作共享服务。代理应限制请求体、连接速率及超时，不信任客户端自行填写的转发 IP。应用登录节流使用实际 socket 地址；学生进入按练习和编号分别限流，另有宽松的地址全局滥用上限，不会因同班共用 Wi-Fi/代理就阻止第 21 位学生。

在正式使用前实际核对外网学生手机访问、音频播放、教师管理、证书、服务器重启后的数据、备份恢复及名单权限。技术测试不代替真实课堂验收。本任务未授权生产部署。

## 数据和恢复

新数据文件是 `data/formal-state.json`，旧 `attempts.json`、`question-bank.json`、`classroom-config.json` 保持原样且不自动导入。旧记录身份和评分可信度不足，迁移须单独审核后显式处理；本版没有自动迁移功能。现有 `supabase/` 是历史预备材料，本服务不会使用它，也没有运行数据库迁移。

每次提交、导入和批阅串行执行，写入临时文件、fsync 后原子替换，并保留替换前的独立备份。会话只保存在内存，服务器重启后需重新登录。持久化目录权限设为 0700、新数据文件为 0600；个人进入码保存带随机盐的 scrypt 摘要，仍须使用足够随机的进入码。备份包含学生作答，须限制服务器帐号访问、加密磁盘和备份，另行保存站外备份并定期恢复演练。自动备份不自动清理，运营人员需要监控空间并订定保留政策；工具不会擅自删除历史数据。

应用以 `formal.lock` 防止两个进程同时写入同一目录。一次只运行一个实例，不支持共享文件系统、多实例或无持久化磁盘的 serverless 部署。正常关闭会释放锁；异常退出留下锁时，先读取锁内 PID，确认原服务确实已停止，再由运营人员移走锁后启动。不要删除仍运行进程的锁。数据 JSON 损坏时启动失败，不以空数据覆盖；停止服务后核对备份，保存故障文件，再显式恢复经过验证的备份。不要在运行期间手动编辑状态文件。

## 验证

```sh
npm test
npm run build
```

集成测试使用 `qa/` 下独立的合成临时目录，不使用真实学生资料。覆盖登录、来源限制、学生隔离、名单、35 人共用代理、字段检查、客观评分、重复/并发提交、版本保留、批阅追加、关闭和重启持久化。可在仓库已安装 Playwright 时运行：

```sh
node test/browser-qa.mjs
```

若 Playwright 的浏览器未安装，可指定已有 Chrome：`BROWSER_EXECUTABLE='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node test/browser-qa.mjs`。验证结果见 `qa/listening-formal-2026-10-04.md`。本应用面向单教师、小规模班级；没有多教师帐号、密码找回、语音录音、离线提交自动同步、正式教材内容、云配置或课堂验收。
