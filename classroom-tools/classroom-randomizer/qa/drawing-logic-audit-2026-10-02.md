# 抽问逻辑检查（2026-10-02）

检查范围：三个子代理分别只读检查抽问池、记录与恢复、界面与跨系统来源；主代理复核当前线上静态文件及既有测试。没有修改程序、执行数据库迁移或部署。

## 当前结论

本地新版的核心规则符合本次要求：本轮已回答的学生（随机、自愿或老师主动叫）退出抽问池，下一轮恢复；重复自愿回答分别计次，但只移除一个学生；缺席学生不参与抽取。老师主动叫保留独立来源，不计为自愿回答。

仍有六个可复现问题，既有测试没有覆盖全部交错操作与界面一致性。线上网站仍是旧版，不能把本地检查通过理解为线上已修复。

## 可复现问题

### 1. 名单筛选与实际抽问池不一致（P2）

- 位置：`app.js:1294`、`app.js:1301`、`src/model.js:357`。
- 操作：三名学生中，甲自愿回答一次，乙由老师主动叫后回答一次。
- 实际：进度为本轮完成 2／3，池中剩 1 人；“尚未抽问”筛选仍显示三人，“本轮已完成”显示没有学生。Chrome 实测，刷新后仍可复现。
- 原因：抽问池已读取本轮 answered attempts，名单仍只读取旧 `answeredStudentIds`。
- 修正方向：名单状态与筛选使用和抽问池一致的完成判定。

### 2. 同一位正在回答的学生可被重复登记（P2）

- 位置：`src/model.js:520`、`app.js:1445`。
- 操作：随机抽中甲 → 为甲点击自愿或老师主动叫＋1 → 保存目前随机回答。
- 实际：＋1后甲仍显示等待回答；随后保存会得到两条 answered，回答总数为 2。
- 影响：同一次回答容易误记两次，连带影响参与统计。两次独立回答可以分别记录，问题在于界面没有区分这两种情况。
- 修正方向：同一位 pending 学生的来源操作应完成或更正当前记录；独立新发言须有明确区分。其他学生在当前抽问期间发言仍应允许。

### 3. “避开上一位”按创建顺序判断，交错发言时认错人（P2）

- 位置：`src/model.js:367`。
- 操作：两名学生，甲随机等待回答 → 乙自愿或老师叫后回答 → 甲完成回答 → 开始下一轮。
- 实际：系统认乙为上一位；下一轮候选池只剩甲，刚回答的甲又被首先抽到。
- 原因：倒序读取 attempts 的创建顺序，没有反映甲较晚完成回答。
- 修正方向：按实际参与／完成顺序判定最近一位，并覆盖交错回答、未回答和撤销场景。

### 4. 连续撤销丢失较早的撤销审计记录（P2）

- 位置：`src/model.js:701`。
- 操作：自愿甲 → 自愿乙 → 撤销乙 → 撤销甲。
- 实际：第二次撤销恢复旧快照后，只保留甲的 undone，乙的原始记录和撤销事件消失。
- 影响：本地 CSV／完整备份不能完整还原撤销过程。正常逐次同步时，队列可能仍保留乙的 voided，尚不能断言云端乙恢复有效。
- 修正方向：撤销业务状态时保留已发生的撤销记录与审计链。

### 5. 悬空 pending ID 的备份可导入并卡住课堂（P2）

- 位置：`src/model.js:1071`、`app.js:1686`。
- 操作：合法备份的 `pendingAttemptId` 改为不存在的 ID，再导入。
- 实际：导入成功并保存；进度认为有 pending，但找不到该回答。抽问、记录回答和下一轮均被阻挡。
- 修正方向：替换当前课堂前核对 pending 引用、记录状态与学生身份；无效备份应被拒绝或明确修复。

### 6. 当前抽问登记缺席时遗漏题目与备注（P2）

- 位置：`app.js:1003`、`src/model.js:545`。
- 操作：抽中学生，填写题目／备注，再以“未回答原因＝缺席”结束抽问。
- 实际：setAbsent 完成缺席记录，没有保存当前题目、questionId 和未提交备注。
- 修正方向：当前抽问的缺席分支应保留和其他未回答原因相同的上下文；直接名单勾选缺席仍是独立考勤操作。

## 合理但需要明确的规则

1. 公平以本轮有没有回答为准，当前没有按整堂或历史回答次数加权。下一轮恢复后，先前自愿多次者仍可能被抽到；这是本次“本轮暂停”的范围。
2. 未回答者回到池中。若最后一名始终不回答，本轮无法自然结束；这是现有设计，不是程序自动失效。若课堂需要跳过学生结束本轮，应另行定义“本轮跳过”，不应把未回答计成已回答。
3. partial、peer_supported 也视为已有回答，因此退出本轮；系统只记录事实与来源，没有新增评分公式。
4. 本轮结束与新题目是不同概念。开始新题目不会自动恢复已回答学生，只有下一轮或新课堂才恢复。
