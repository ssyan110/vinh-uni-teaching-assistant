## 1. 產品定位

教師先選擇班級、教材與課次，提問後從本堂課的可參與學生中隨機抽出一人。學生回答後，教師記錄回答狀態即可完成本輪；不需要輸入分數或等待評分。已完成的學生在本輪不再被抽到；尚未回答的學生仍留在 drawing pool 裡。

本工具是跨課次共用的課堂工具，不是教材、PPT、教師手冊或課次 authority。它應該簡單、離線、能在投影時使用，保留教師的判斷，並留下可追溯的抽問與回答原始資料；評分責任在另一個系統。

## 2. 專案位置決定

### 決定

第一版放在本專案的：

`classroom-tools/classroom-randomizer/`

這個位置目前是合適的，理由是：

- 首要使用者與實際課堂都在榮市大學。
- 根目錄的 `classroom-tools/README.md` 已預留 `classroom-randomizer`，並將它定義為跨課次工具。
- 它可以沿用本專案的離線、投影、可存取性與課堂 QA 原則。
- 它能與 `student-tracker` 共用同一個 Supabase 專案與 CSV 名冊格式，但保留自己的抽問資料表與操作邊界。

### 邊界

- 工具維持自己的 `README`、程式碼、測試與資料格式。
- 不放在 `lessons/*`，不寫入 `20-approved/`、`30-qa/` 或 `40-release/`。
- 不依賴任何特定教材、課號或 `lesson_key`。
- 抽問工具直接連接 Supabase；雲端是課堂與抽問紀錄的主要資料來源。
- 瀏覽器本機只保存離線工作狀態、待同步佇列與教師主動下載的備份，不取代雲端紀錄。
- 學校點名系統仍是出席資料的獨立來源；本工具不把缺席自動改成未回答，也不要求教師在兩個系統重複維護出席。

### 何時抽成獨立 repository

當工具開始服務第二所學校／第二位教師，需要獨立版本發布、雲端同步或獨立產品文件時，再抽成 `classroom-randomizer` 獨立 repository。現在提前拆開會增加管理成本，也尚未帶來實際收益。

### Customer-facing terminology

內部資料仍可使用穩定的英文欄位名稱；教師畫面使用以下課堂語言：

| 內部欄位 | 教師畫面用語 |
| --- | --- |
| `session` | 本堂課／課堂紀錄 |
| `round` | 第 X 輪抽問 |
| `drawing pool` | 可抽名單／尚未完成名單 |
| `pending` | 等待回答 |
| `pass` | 完成本輪／回答完成 |
| `rubric` | 本工具不使用 |
| `backup` | 課堂備份檔 |
| `attempt` | 抽問紀錄／回答紀錄 |

customer-facing UI 不直接顯示資料模型、開發進度或內部欄位名稱。

### 顯示邊界：教師操作台與課堂投影

這不是一個需要向學生解釋自己的產品頁面，而是一個教師在課堂中反覆操作的工具。因此，課堂畫面不顯示產品標語、規則說明、教師備註、資料儲存、備份或開發狀態，也不顯示任何評分控制。

- 教師操作台：顯示課前設定、抽問控制、回答狀態、學生狀態與資料匯出。
- 學生畫面：以獨立視窗顯示班級、教材、課次、第幾輪、目前抽到的學生、回答要求與思考時間。
- 教師操作台與學生畫面同步更新；教師紀錄、學生名單狀態、課堂紀錄與檔案操作不出現在學生畫面。
- 「一堂課，一個新的循環」等產品定位文字只適合產品介紹或需求文件，不放在學生會看到的課堂工作畫面。

## 3. 已確認的核心規則

以下規則來自教師目前的明確決定與研究後確認：

1. 每次上課都是新的 session；開始新 session 時重新建立候選名單，不承接上一堂課的完成狀態。
2. 抽到學生後，學生先進入「等待回答」狀態，不會自動完成本輪。
3. 學生回答後，教師按下「記錄回答」即可從本輪 drawing pool 移除；不需要輸入或等待分數。
4. 沒有回答的學生仍留在 drawing pool 裡，之後可以再次被抽到。
5. 本輪所有可參與學生都完成回答後，本輪結束；下一輪重新讓這些學生進入候選名單。
6. 學生回答後，教師可記錄回答狀態、回答情境與備註；「已抽到」不等於「已回答」，但本工具不判定回答品質，也不產生分數。
7. 自願發言是獨立的課堂事件：要留存並與隨機抽問分開統計，但不會消耗本輪隨機抽問名額。
8. 每次回答都保存獨立原始紀錄；同一學生同一課回答五次，就保留五筆，不合併、不只保留最後一次。
9. 「隨機／自願」只區分事件來源；本工具不設定成績權重、不計算成績，正式評分由另一個系統負責。

### 術語與計算

- `session`：一次上課，開始時全新建立。
- `round`：同一 session 中的一次完整循環。
- `eligible students`：本堂課可參與、未被排除的學生。
- `answered students`：本輪已回答並由教師確認完成的學生。
- `raw response`：一筆保存回答狀態、來源、情境與備註的課堂原始紀錄；不包含本工具產生的分數。
- `drawing pool`：`eligible students - answered students`。
- `pending student`：目前被抽到、正在等待教師確認結果的學生。
- `not_selected`：本輪尚未被抽到，不是未回答。
- `no_response`：學生實際被抽到但沒有回答；必須保存一個未回答原因，且學生留在 drawing pool。
- `record summary`：按學生、課次與事件來源顯示抽問、回答、未回答與自願發言次數；不計算平均或成績。

## 4. 建議採用的課堂流程

1. 教師按「開始新 session」。
2. 從班級下拉選單選擇本班；教學資料庫名冊自動載入，必要時可編輯或匯入其他名單。學校出席狀態由點名系統管理；本工具只可把學生暫時設為「暫不抽問」。
3. 教師提問，按「抽一位」。
4. 畫面顯示座號／姓名與「等待回答」。
5. 學生回答後，教師在同一個面板選擇回答狀態，可按「記錄回答並抽下一位」直接繼續；該學生離開本輪 drawing pool。
6. 不需要另開評分面板，也沒有待評分流程；回答狀態、情境與備註都是可選的原始紀錄。
7. 學生沒有回答時，教師先選擇原因，再按「記錄未回答」。該學生回到 drawing pool，不算完成本輪。
8. 重複以上流程，直到畫面顯示「本輪完成」。
9. 教師需要繼續時，按「開始下一輪」；系統重新加入所有 eligible students。

### 尚未由教師鎖定、但建議作為 MVP 預設值

- 同一時間只保留一位 pending student，避免教師忘記上一位的回答結果。
- 按「記錄未回答」後，未回答學生仍在 pool，但若還有其他候選人，暫時避免立即再次抽到同一人；這不改變其仍可被抽到的資格。
- 下一輪由教師手動開始，不自動切換，避免在課堂轉場時突然抽人。
- 暫不參與抽問者標為「暫不抽問」，不算已回答，也不阻塞本輪完成；真正缺席仍由學校點名系統管理。
- 「完成本輪」只代表教師已記錄這次回答，不代表本工具判定語言表現；正式評分由另一個系統處理。

## 5. MVP 需求範圍

### 5.1 名冊與 session

- 支援貼上名單與 CSV 匯入。
- 班級名稱使用固定下拉選單，目前提供 `LT_01`（27 人）、`LT_02`（30 人）、`LT_03`（14 人）；選班級後自動載入對應名冊。
- 資料庫名冊載入後只保留抽問與原始紀錄需要的學號、學生姓名與座號；教師可在開課前修改當堂 snapshot。
- 教師必須從教材下拉選單與課次下拉選單選擇本堂課內容；《準中級加速篇 I》提供第 1–12 課，《中級衝刺篇 I》提供第 1–8 課。
- 至少辨識：學號／座號、學生姓名；若只有姓名也可以使用，但需提示可能有重名。
- 教師可以把學生標記為本堂「暫不抽問」；缺席、請假與出席狀態由學校點名系統保留，未來以 `student_id + class_id + session_date` 匹配匯入。
- 新 session 不帶入上一堂的 answered、pending 或 excluded 狀態。
- 每個 session 保存當時的名冊 snapshot 與抽問設定，避免日後名冊變更影響歷史資料。
- session 中途重新整理頁面後，可以恢復目前狀態。

### 5.2 抽取與結果

- 「抽一位」只從目前 drawing pool 抽取。
- 隨機選擇不可因為學生先前回答過其他課而降低或提高機率。
- 抽到後顯示「等待回答」，不得自動移除或自動 pass。
- 「記錄回答」才會把學生加入本輪 answered set；記錄動作不需要分數。
- 「記錄未回答」會把學生留在 drawing pool，並要求保存「沒有準備、聽不懂題目、一時想不起、緊張／不舒服、時間不足、選擇跳過、其他」其中一個原因。
- 學生回答後記錄回答狀態即可完成本輪；本工具不提供 rubric、待評分、補評或分數修改。
- 每次抽取或自願發言都留下 attempt record，包括來源、回答結果、未回答原因、回答情境、教師備註、修正與撤銷狀態。
- 提供「撤銷上一個結果」，讓教師能修正誤按。
- 顯示本輪進度，例如「已回答 8／30，剩餘候選 22 人」。
- drawing pool 為空時，顯示本輪完成，不再提供普通抽取動作。
- 開始下一輪前要求教師明確按鈕確認。

### 5.3 課堂操作

- 教師需先登入帳號才能開始一堂新課；登入後即使課堂中暫時離線，仍可繼續操作，資料會在連線恢復後自動同步。
- 可用全螢幕投影。
- 抽取、已回答、記錄未回答、撤銷、開始下一輪等主要動作必須有大按鈕。
- 支援鍵盤操作；焦點位置清楚可見。
- 投影畫面只顯示學生需要看到的座號／姓名與目前狀態，不顯示備課註記、技術資訊或內部資料。
- 重新開始 session、清除名冊或清除紀錄等高風險操作需二次確認。

### 5.4 記錄與資料

- 每次狀態變更先保存到本機工作狀態，並立即排入 Supabase 同步；Supabase 是持久保存的主要資料來源。
- 每堂課保存一筆 `randomizer_sessions`，包括班級、日期、教材、課次、目前輪次、暫不抽問名單與本輪完成狀態；真正出席狀態由學校點名系統保存。
- 每次抽到、回答、未回答、自願發言與撤銷都保存為 `randomizer_attempts`；同步使用 client idempotency key，重試不重複建立資料。
- 本工具只同步自己的抽問原始紀錄，不寫入學生追蹤系統的評量事件。
- 每次事件記錄 session 日期、班級名稱、教材、課次、事件順序、學生、round 編號、事件來源、機會狀態、回答結果、未回答原因、回答情境、修正狀態與教師備註。
- CSV、Excel 與 JSON backup／restore 都以逐筆原始紀錄為主，另提供每位學生的跨課次參與次數摘要；不輸出分數或平均。
- 歷史 session 不設定自動淘汰上限；若瀏覽器儲存空間不足，必須明確警告教師下載 JSON backup，不得靜默刪除舊紀錄。
- 不做自動語音辨識、不自動判定回答品質、不把「已抽到」誤記成「已回答」。
- 不把「未準備但回答」轉成分數；只保存回答情境，讓教師日後在另一個系統處理評分。

## 6. 舊版評分設計（歷史封存，不再實作）

### 6.1 Rubric 選擇原則

建議採用「ACTFL-aligned classroom analytic rubric」：以 ACTFL Performance Descriptors 的課堂表現範圍作基礎，以 ACTFL Proficiency Guidelines 2024 的 FACT（功能與任務、準確度、情境與內容、文本類型）協助設定每一題的目標，再用 NCSSFL-ACTFL Can-Do Statements 寫出學生今天要完成的 Can-Do。

這份 rubric 是教師的課堂評量工具，不是官方 ACTFL rating。單次回答是一次 performance evidence；學生的整體 proficiency 應該從多次、不同任務與不同情境的證據判斷。工具畫面使用「課堂分數／表現分數」，不使用「ACTFL 等級」作為單次回答結果。

參考來源：

- [ACTFL Performance Descriptors for Language Learners](https://www.actfl.org/educator-resources/actfl-performance-descriptors)：適合描述明確教學後的課堂表現，包含 Intermediate 的功能、文本類型、語言控制、詞彙與溝通策略。
- [ACTFL Proficiency Guidelines 2024](https://www.actfl.org/proficiency-guidelines-overview)：用 FACT 幫每個題目設定可觀察的表現目標。
- [NCSSFL-ACTFL Can-Do Statements](https://www.actfl.org/educator-resources/ncssfl-actfl-can-do-statements)：用來寫學生任務目標與追蹤成長，不直接當作數字成績表。
- [ACTFL 使用與正式 rating 說明](https://www.actfl.org/use-actfl-proficiency-guidelines-and-issuing-of-official-actfl-tests)：課堂教師可以使用 Guidelines 做課堂評量，但非官方測驗不得宣稱發出正式 ACTFL rating。

### 6.1.1 越南與榮市大學制度參考

- [榮市大學 2023 年學習結果評量與管理規定](https://phonghcth.vinhuni.edu.vn/hoat-dong-chuyen-mon/seo/quy-dinh-ve-danh-gia-va-quan-ly-ket-qua-hoc-tap-trong-dao-tao-trinh-do-dai-hoc-he-chinh-quy-va-dao-tao-trinh-do-thac-si-tai-truong-dai-hoc-vinh-111889)：用來確認學校正式評量規範的制度背景。
- [越南教育部 56/2026/TT-BGDĐT 通告](https://vanban.chinhphu.vn/?docid=219044&pageid=27160)：現行高等教育評量制度的官方參考來源。
- [榮市大學公開課程評量示例](https://khoaspnn.vinhuni.edu.vn/hoat-dong-chuyen-mon/seo/ban-mo-ta-chuong-trinh-dao-tao-nganh-su-pham-tieng-anh-104663)：示例中把過程評量與期末評量分開列出；這只是公開課程文件的參考，不代表本華語課程已採用相同百分比。

本工具因此只保存可查核的課堂過程性證據；自願發言可以在未來課程公式中成為較高比重的參與項目，但正式比例必須先依本課程核准的 syllabus／評量規定公開確認，不能由工具自行推定。

### 6.2 MVP 預設 rubric：課堂口語回應 0–3 分

每次回答評 4 個面向，每項 0–3 分，總分 0–12。題目建立時要先設定 `task_mode` 與 `task_target`：預設 `interpersonal_listening_speaking`，再選短答、連貫回答或互動問答；「內容延伸／互動策略」依該目標評分，不要求每一題都講長篇。

本工具的隨機點名預設測量的是「聽懂教師問題並回應」的人際聽說表現。若活動改成聽音檔後找主旨、細節或推論，應改用 `interpretive_listening` task mode 與另一份針對聽力證據的 rubric；不能直接把同一個 0–12 分解讀成完整聽力能力。

| 評量面向 | 0 分 | 1 分 | 2 分 | 3 分 |
| --- | --- | --- | --- | --- |
| 聽懂問題並完成任務 | 有回答，但沒有回應題意 | 只完成部分要求，需多次提示 | 回應大致切題，少量要求未完成 | 直接回應題意並完成本題目標 |
| 表達清楚度 | 大部分訊息無法理解 | 常需要重複或猜測 | 大致聽得懂，偶有中斷 | 發音、聲調和語速讓同伴容易聽懂 |
| 句式與詞語運用 | 語言不足以傳達主要訊息 | 主要依靠零散或背誦語塊，錯誤常阻礙理解 | 能使用本題需要的句式與詞語，錯誤通常不阻礙理解 | 能選用合適的句式與詞語，表達穩定 |
| 內容與互動 | 沒有可用的內容或互動證據 | 回答很短，需大量教師引導 | 能達到本題要求的長度／細節，必要時可重說或澄清 | 能依題目補充細節、澄清或追問 |

評分規則：

- 沒有回答不是 0 分，而是 `not_answered`；學生留在 drawing pool。
- 回答內容不正確但確實回答，可以得到 0–12 分中的相應分數，並完成本輪 pass；pass 與語言表現分開保存。
- 每筆分數要保存 rubric 版本與各項原始分數，不能只保存換算後的百分比。
- 「未準備但回答」不是另一個準備分；教師只評這一次回答的綜合口語表現，並把回答情境另存為 `unprepared`。
- 原始 rubric 摘要中的每次計分回答等權；教師可以把某筆標記為「不納入課堂摘要」，但不刪除原始資料。
- session summary 顯示每位學生的總事件數、回答次數、有效回答次數、隨機抽問次數、自願發言次數、未回答原因、原始平均與各面向平均；正式學期總評公式不在 MVP 中硬編碼。

### 6.3 成績計算邊界

本工具保存的是教師的課堂過程性證據，不是榮市大學的正式成績系統。學校的期中考、期末考與正式課程成績仍由學校系統管理；本工具不自動寫回，也不把課堂分數直接拼成官方總分。

因此，MVP 只提供兩層資料：

1. **原始事件**：每一次隨機抽問、自願發言、回答結果、未回答原因、回答情境、rubric 細項、教師備註與修正紀錄。
2. **描述性摘要**：按學生、課次與事件來源顯示次數、有效回答次數與原始平均；所有摘要都標示「不代表正式課程成績」。

如果日後要把課堂參與納入正式課程總評，仍須由教師依 syllabus／學校規定另行確認、公開並在學校系統計算。原始資料不可被倍率覆寫，才能在學期末重新計算、修正或提供查核。

### 6.3.1 自願回答與隨機避重（2026-09-08 確認）

- 自願回答不限次數，每次都可評分並獨立記錄；不因連續發言或超過三次而限制。
- 自願回答不消耗本輪隨機抽問資格；隨機回答完成後仍可自願回答。
- 有其他候選人時，隨機抽問避開最近一筆未撤銷事件的學生；適用於自願發言、隨機抽問與跨輪。撤銷和備份恢復後按有效事件重新判斷。
- 只剩同一位候選人時，教師確認後可再次抽問，取消則維持原狀。
- 一次處理一位學生；目前回答完成後才開始下一筆自願或隨機回答。
- 移除綜合指數與其封頂公式，介面和 CSV 只保留實際次數、原始分數與描述性平均；不改寫歷史回答。

### 6.4 必須留存的資料

每筆 `attempt` 至少包含：

- `attempt_id`、`session_id`、`round_number`、`student_id`。
- 名冊 snapshot 中的座號、學生姓名與其他必要識別資料。
- `textbook_id`、`lesson_id`、`task_mode`、`task_target`、抽取時間與完成時間；MVP 不要求保存每個小問題的題目文字。
- `event_type`、`opportunity_status`、`response_status`、`no_response_reason`、`answer_context`、`attendance_status`。
- `outcome`：`pending`、`answered`、`not_answered` 或 `undone`。
- `not_selected` 只表示本輪還沒被抽到，不是 0 分；`no_response` 只表示實際被抽到但沒有回答。
- `assessment_status`：`scored`、`pending` 或 `not_applicable`。
- rubric 版本、四項 rubric 分數、總分、是否列入課堂摘要與教師備註。
- `record_status`、事件順序、修改時間、修正備註；撤銷採標記方式，不直接刪除原始 attempt。

歷史 session 必須可查看、編輯待評分項目、修正已保存分數、匯出 CSV／Excel，並與新的 session 分開計算。新的 session 只重置抽取資格，不清除歷史評分。

## 7. 舊版不納入 MVP（歷史）

- AI 語音評分或自動判斷學生是否回答。
- 學生手機登入、即時多人連線與公開網路服務。
- 以分數改變抽取機率、排行榜、懲罰機制或把未回答直接視為負面分數。
- 隨機分組、配對最佳化與其他大型 classroom toolkit 功能。
- LMS、出勤資料庫或學校正式成績系統的直接寫回。
- 依全學期課程規則自動計算正式總成績或直接寫回學校成績系統。

## 9. 舊版驗收條件（歷史）

### AC-01：完整一輪不重複 pass

建立 30 位 eligible students。教師反覆抽取並對每位按「已回答」。在本輪完成前，任何已按「已回答」的學生都不得再次出現在普通候選池中；完成後必須顯示 30／30。

### AC-02：未回答不算 pass

抽到 5 號學生後按「記錄未回答」，不按「已回答」。5 號的 answered 狀態必須仍為 false，且之後仍能被抽到；系統不得把未回答視為完成。

### AC-03：下一輪重新加入

30 位學生全部已回答後，普通抽取必須停止。教師按「開始下一輪」後，30 位 eligible students 全部重新可抽；上一輪的紀錄仍保留。

### AC-04：新 session 完全重置

上一堂課的 5 號已回答，開始新 session 並載入同一名冊後，5 號必須重新在 drawing pool 中，不能承接上一堂的 pass 狀態。

### AC-05：暫不抽問不阻塞

將 3 位學生標為「暫不抽問」後，這 3 位不得被抽到；其餘 27 位全部回答後，本輪應完成為 27／27，而不是等待這 3 位。真正缺席狀態不在本工具內重複維護。

### AC-06：撤銷可恢復

教師誤按「已回答」後使用撤銷，該學生必須回到 drawing pool，且本輪 answered 數量減一。

### AC-07：中途恢復

抽到學生或完成回答後重新整理頁面，session、round、pending、answered 與 excluded 狀態不得遺失。

### AC-08：課堂中暫時離線可用

教師已登入並成功載入名單後，課堂中暫時沒有網路時仍能抽取、標記結果、重新開始下一輪與恢復狀態；首次登入與首次從教學資料庫載入名單需要網路。

### AC-09：回答後必須能評分並留存

抽到 5 號學生，學生回答後，教師填寫四項 rubric 分數並儲存。系統必須保存學生、session、round、題目、rubric 版本、四項分數、總分與時間；完成後 5 號離開本輪 drawing pool。

### AC-10：未回答不產生 0 分

抽到 5 號學生後選擇「沒有準備」並按「記錄未回答」。系統必須留下 `not_answered` attempt 與原因，但不得建立 0 分 rubric；5 號仍在 drawing pool，且仍可再次被抽到。

### AC-11：待評分可補回

教師把已回答學生標成「待評分」後，該學生不再被本輪抽到，且待評分清單顯示該筆資料。之後補入 rubric 分數，該筆狀態改為 `scored`，原本的 session、round 與抽取時間不變。

### AC-12：新 session 保留歷史分數

完成 session A 後建立 session B。同一名學生在 session A 的分數仍可查詢；session B 的 drawing pool、round 與統計從零開始，不承接 session A 的 pass 狀態。

### AC-13：原始資料與摘要分開

將一筆回答標為「不納入課堂摘要」。該筆仍出現在歷史、CSV 與 Excel 原始紀錄中，但不計入摘要平均；若改回納入，摘要應重新計算。原始評分仍保留。

### AC-14：匯出資料可追溯

CSV 與 Excel 必須能逐筆還原學生、教材、課次、round、事件來源、回答結果、未回答原因、每項 rubric 分數、總分、是否納入課堂摘要、待評分與撤銷狀態。JSON backup 還原後，session 與分數不得遺失。

### AC-15：單次分數不冒充 ACTFL 等級

介面與匯出結果只能顯示課堂 rubric 分數／表現摘要，不得把單次 0–12 分自動標成 Novice、Intermediate 或其他正式 ACTFL proficiency rating。

### AC-16：自願發言不破壞隨機公平性

教師搜尋並選擇一位學生記錄「自願發言」，完成評分後該筆紀錄必須標示來源為自願發言；該學生仍在本輪 drawing pool，之後仍可被隨機抽到。

### AC-17：抽問資料完整保存到雲端

教師登入後開始一堂課，依序完成一次抽到、未回答、回答待評分、補評、自願發言與撤銷。Supabase 的 `randomizer_sessions` 與 `randomizer_attempts` 必須保留每種狀態、學生、教材、課次、輪次、時間、備註與評分；已評分回答另外出現在 `learning_events`。重新送出同一筆資料不得產生重複列。

### AC-18：暫時離線後自動同步

課堂中暫時失去網路時，教師仍可完成抽問與評分；畫面清楚顯示待同步狀態。恢復連線後，所有待同步課堂與抽問紀錄自動送出，且資料庫筆數與本機課堂紀錄一致。

### AC-19：自願發言與隨機抽問分開統計

同一學生完成兩次隨機抽問與三次自願發言後，原始紀錄必須保留五筆；摘要必須分別顯示隨機抽問 2 次、自願發言 3 次，且自願發言不會讓學生離開本輪隨機 pool。

### AC-20：同一課次的多次回答不合併

同一學生在第 1 課保存五次回答與五筆分數後，學生課堂匯總必須顯示五次回答；每筆事件的時間、來源、分數與備註都可以在原始紀錄匯出中逐筆查回。

### AC-21：不把抽取機率當作成績權重

系統可以優先抽取較少被隨機抽到的學生，但不能因為自願發言或隨機抽問而修改原始分數。任何未來總成績加權都必須由教師另行確認公式，並以計算檢視呈現。

## 10. 非功能需求

- 啟動後不需要設定伺服器或 API key；教師以既有帳號登入後使用。
- 常用課堂動作應在一個畫面完成，避免教師在提問後切換多個頁面。
- 投影文字、按鈕與目前學生必須在教室後排可讀。
- 抽問後的回答狀態應在同一個紀錄面板完成，不要求教師切換到另一個頁面。
- 所有互動控制要有明顯 focus 狀態，且不能只依賴顏色傳達結果。
- 任何「清除 session」動作都要可辨識、可確認，避免誤刪課堂紀錄。
- 學生資料與課堂紀錄保存於 Supabase，所有資料表啟用 RLS 並限制為登入教師本人；本機只作離線工作與備份。
- 清除名冊或歷史資料前必須提示先匯出 backup；系統不得因開始新 session 而自動刪除舊紀錄。
- 中文使用 `KaiTi`／標楷體系列；越南文、英文、數字與其他拉丁字母使用 `Times New Roman`。CSS 以 `Times New Roman` 優先、中文楷體 fallback 實作混合文字字體分流。

## 11. 目前已採用的決策

1. 「記錄未回答」後學生仍在 pool；若還有其他候選人，暫時避免立即再次抽到同一人。
2. 教師介面使用簡體中文；學生姓名保留名冊原字形。
3. 名冊同時支援貼上與 CSV，並相容 `student-tracker` 的核心欄位。
4. 本工具不提供、不保存、不同步分數、評量表、待評分或平均；正式評分由另一個系統負責。
5. 每一筆回答、未回答、自願發言與修正都保留原始事件；未回答原因與回答情境獨立保存。
6. 雲端只接收本工具自己的 `randomizer_sessions` 與 `randomizer_attempts` 原始紀錄，不寫入學生評量事件。
